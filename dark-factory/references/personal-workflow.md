# Personal approved-goal workflow

Load only for an admitted personal project. Read the goal, exclusions, acceptance criteria, priority, and permitted actions from private policy. Choose useful unfinished tasks autonomously within that approved goal. New projects, changed product scope, paid spend, public/release authority, and deployment require the appropriate owner decision unless already granted explicitly.

The project execution owner decomposes work, assigns isolated workers, applies project checks and the shared [R0/R1/R2 policy](orchestration/review-policy.md), and verifies material results. Ordinary code may merge under the run's explicit merge authority only after all required checks and reviews and the project's integration gate. Use [merge-gate.md](merge-gate.md) when that strict gate is selected; preserve stronger repository rules. Merge authorization does not authorize deployment, release, user-install upgrades, settings changes, or replies to people.

A scoped personal manager may reprioritize, pause, and resume admitted work within its allocation. Record the reason and checkpoint. When reserve, readiness, or a required review blocks execution, preserve the task and select independent authorized work. Do not create work to consume spare subscription capacity.

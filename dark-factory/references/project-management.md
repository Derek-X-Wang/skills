# Single-project supervisor

Use for a session already supervising one project or explicitly assigned that role. Applying Dark Factory preserves that scope. It does not appoint a multi-project manager or require one to exist.

## Intake and ownership

Identify the named project, current execution owner, approved goal, standing authority, workers, and current canonical record. A known owner continues as owner; an ordinary worker stays a worker. If another session owns this same project, reconcile ownership before changing shared records or overlapping work. Follow [orchestration](orchestration.md) for project-local delegation/review and [continuation](continuation.md) for an actual owner replacement.

The standalone topology is human ↔ project owner ↔ this project's workers/reviewers. Under an explicitly assigned factory, the project owner reports to that factory manager instead. Peer project supervisors do not acquire authority over each other's queues, sessions, load, or quota merely because they share a machine.

## Apply the relevant rules

Load the project's personal/Bite workflow, its review/integration gates, [records](records.md), and [capacity policy](capacity-and-fleet.md). If unattended, add [unattended operation](unattended.md). Use the default state location and recorded project identity; preserve existing authority and active writers during migration.

Checking capacity, recording known authority, and maintaining a checkpoint within an authorized private location are ordinary project management. Adopting these rules does not require repeated owner approval. Ask only for missing product/authority decisions, conflicting ownership, or a genuinely required storage exception. Do not request a separate decision to postpone unrelated multi-project management.

Use sufficiently fresh relevant quota evidence before dispatch; unknown applicable short windows remain unknown. Fixed freshness intervals, reserve percentages, thresholds and concurrency limits come from approved policy and relevant evidence, not invented defaults. Record bounded uncertainty and required provisional-call authority. A healthy weekly status is not proof that every applicable limit permits parallel work.

Observe other projects' load and protect this project's authorized resource budget; leave their processes and allocations to their owners. Apply an existing shared allocation if one is actually authorized. Without global allocation evidence, do not claim a global reservation or assert that unobserved competing work is absent. Reduce this project's new admissions when measured capacity is insufficient.

At assignment, merge, decision, pause or handoff, update the project checkpoint and evidence. Return this project's results, blockers and cleanup to its actual parent/human. Keep already-authorized work moving while dependent scope or ownership questions are parked.
